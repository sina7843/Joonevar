# ماتریس مجوز سرور — شش Context بازیگر

مبنا: Requirements §۴، §۲۱، §۲۳.۴ و ماتریس Flow Map `2:6`. این سند قرارداد لایه `src/authz` است.

## ۰. اصول غیرقابل‌مذاکره

1. **هر اقدام رکورد‌محور روی سرور مجوزسنجی می‌شود.** قفل UI هرگز تنها کنترل نیست. حذف قفل در کلاینت نباید هیچ اثری در دیتابیس بسازد.
2. **داشتن Shell ≠ داشتن همه اختیارات.** عضو عملیاتی فقط اقدام‌های مجاز خودش را دارد.
3. **مجوز دو بُعد دارد:** Actor مجاز است؟ **و** این رکورد مشخص متعلق به همان Actor است؟ تغییر URL یا کد مراجعه نباید یکی را دور بزند.
4. **بازبررسی پس از ورود مجدد.** Resume از اعلان یا Draft، دسترسی را دوباره ارزیابی می‌کند.
5. **دانلود فایل خصوصی** فقط از مسیر سرور با همان دو بُعد.
6. Context عمومی (کاربر/پرورش‌دهنده/دامپزشک) با Shell عملیاتی (انجمن/مرکز ژنتیک/سوپرادمین) قاطی نمی‌شود (D11).

## ۱. شش Context

| Context | نحوه فعال‌شدن | نمایش | حوزه |
|---|---|---|---|
| `USER` | هر حساب واردشده | Context پایه | حساب خود، حیوان‌های خود، درخواست‌ها، اسناد، تأییدهای مجاز |
| `BREEDER` | فقط اگر نقش برای حساب فعال باشد | Role Switcher (پویا) | امکانات پرورش و کنل + همه دسترسی‌های USER |
| `TRUSTED_VET` | فقط با نقش تأییدشده | Role Switcher (پویا) | مراجعه‌های **تخصیص‌یافته به خودش**، میکروچیپ، نمونه، ارسال، تأیید دامپزشکی |
| `ASSOCIATION_OPERATOR` | انتساب عملیاتی | Shell مستقل | صف عضویت/عضو، کنل، مجوز جفت‌گیری، شجره‌نامه خارجی |
| `GENETICS_OPERATOR` | انتساب عملیاتی | Shell مستقل | فیش، دریافت/اعتبار نمونه، پردازش، نتیجه، اعتراض |
| `SUPERADMIN` | انتساب عملیاتی | Shell مستقل | مدیریت عملیاتی و تنظیمات در حد مجوزهای مصوب |

Role Switcher **تعداد متغیر** دارد و فقط Contextهای فعال را نشان می‌دهد. نقش غیرفعال برای پرکردن اسلات ثابت نمایش داده نمی‌شود. سوپرادمین/انجمن/مرکز **در سوییچر عمومی نیستند** (D10, D11).

## ۳. اثر عضویت غیرفعال دامپزشک (D05)

| مورد | رفتار |
|---|---|
| نقش، تاریخچه، Locationها | **حفظ می‌شوند** |
| نمایش در Finder برای درخواست جدید | حذف |
| تخصیص درخواست جدید | ممنوع |
| Check-in و تکمیل درخواست‌های **قبلاً فعال** | **مجاز** |
| ثبت نتیجه روی پرونده‌های فعال قبلی | مجاز |
| فعال‌شدن دوباره عضویت | محدودیت را بدون Onboarding مجدد رفع می‌کند |

پیاده‌سازی: بررسی عضویت در **پذیرش کار جدید** انجام می‌شود، نه در بارگذاری کل پنل. تعلیق عمومی صفحه ممنوع است. این با `REJECTED` شدن نقش دو وضعیت مستقل‌اند.

## ۴. الگوی مشترک صفحات بررسی (§۲۱.۵)

`فهرست → جزئیات → داده و مدارک مجاز → تاریخچه → اقدام متناسب با مجوز → ثبت دلیل در اصلاح/رد → به‌روزرسانی پرونده + اعلان`

هر اقدام صف عملیاتی سه بررسی سرور دارد: Context درست ∧ رکورد در دامنه همان صف ∧ وضعیت فعلی رکورد اجازه این گذار را می‌دهد. «رد» و «نیازمند اصلاح» **دلیل اجباری** دارند.

## ۵. آنچه هیچ Context اجازه ندارد

- ثبت نتیجه دامپزشکی یا نتیجه مرکز ژنتیک از Context عمومی کاربر.
- پردازش درخواستِ دامپزشک دیگر با تغییر URL یا کد مراجعه.
- اتصال چیپ دوم به یک حیوان، انتقال چیپ، یا حذف سابقه برای رفع Conflict.
- بازنویسی نتیجه رسمی توسط کاربر معترض.
- عبور از `PENDING_BOTH_OWNERS` با تأیید یک طرف یا با پرداخت.
- بازگرداندن Gate بررسی انجمن به‌عنوان شرط فعال‌سازی عضویت (D04).
- ساخت انقضا/تمدید عضویت، Time Slot، انتخاب مرکز ژنتیک یا Onboarding عمومی دامپزشک.
