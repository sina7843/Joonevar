## ۴. CI

`.github/workflows/ci.yml` با چهار job: static (typecheck، تست‌های بدون پایگاه‌داده، build و نگه‌داشتن artifact)، database (Postgres یکبارمصرف، مهاجرت، seed، کل سوییت پایگاه‌داده)، browser (همان build، Chromium، کل سوییت مرورگر)، و audit (گزارشی، نه دروازه).

دو قاعده‌ای که در خود فایل اجرا می‌شوند:

- **هیچ secret مخزن خوانده نمی‌شود.** پایگاه‌داده یک service container یکبارمصرف با رمز آشکار است؛ عمداً آشکار، چون چند دقیقه عمر دارد و از جای دیگری در دسترس نیست.
- **ارائه‌دهنده نمایشی محلی هرگز fallback تولیدی نمی‌شود.** محیط CI برابر `APP_ENV=development` و `INTEGRATION_MODE=local` است؛ `assertNotProduction` ساخت این آداپتورها را در production رد می‌کند و مسیر PROVIDER پیاده نشده است. پس **سبز بودن CI هرگز شاهد کارکردن ارائه‌دهنده واقعی نیست.**

CI هنوز روی GitHub اجرا نشده است: این مخزن remote ندارد و push مجاز نیست. اولین اجرای واقعی پس از اتصال remote انجام می‌شود.
