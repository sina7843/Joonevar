# تصمیم‌های لازم از مالک محصول

این فهرست از گزارش مغایرت طراحی و کد (۲۳ مهر ۱۴۰۵) درآمده است. این موارد فقط با داده، تنظیم یا رفتار تازه پیاده می‌شوند. قاعده پروژه می‌گوید رفتار محصول بدون تصمیم ثبت‌شده عوض نمی‌شود.

**روش کار Claude Code:**

1. بخش ظاهری هر مورد را که داده تازه نمی‌خواهد همین حالا بسازد، با حالت پنهان یا «تعیین‌نشده» طبق سیستم طراحی.
2. پیش از هر تغییر داده یا رفتار، این فایل را با پیشنهاد خودش برای هر مورد به مالک محصول نشان بدهد و منتظر جواب بماند.
3. پس از جواب، هر تصمیم را با یک DEC ثبت کند و فقط موارد تأییدشده را بسازد.

**گزینه‌ها برای هر مورد:** «انجام شود» · «فقط بخش ظاهری» · «فعلاً نه (در GAPS ثبت شود)».
