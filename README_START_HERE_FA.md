# بسته اجرای همزیست برای Claude Code

این زیپ برنامهٔ اجرایی اختصاصی همزیست است: ۲۰ پرامپت ترتیبی بر اساس تمام سند مرجع نسخه 1.1، به‌همراه Runner، قواعد کلاد، نگاشت نیازمندی و معیار پذیرش. کد اپلیکیشن هنوز در این بسته پیاده‌سازی نشده؛ کلاد باید آن را بسازد یا کد موجود را تکمیل کند.

## شروع سریع

۱. زیپ را Extract کن. برای پروژه جدید، پوشه خروجی ریشه پروژه است. برای کد موجود، محتوای بسته را در ریشه همان مخزن قرار بده؛ فایل‌های هم‌نام یا .claude موجود را بدون بررسی overwrite نکن. می‌توانی کلاد را در مخزن موجود باز کنی و بخواهی قواعد/بسته را با حفظ فایل‌های فعلی ادغام کند.

۲. Node.js و Git و Claude Code باید در محیط نصب و Claude وارد حساب شده باشد. اتصال Figma اگر موجود باشد برای خواندن رفرنس‌ها استفاده می‌شود؛ توکن یا رمز را داخل چت/فایل کامیت‌شده نگذار.

۳. در پوشه پروژه:

```bat
RUNNER.cmd doctor
RUNNER.cmd check
RUNNER.cmd start
```

`start` کلاد را با دستور START_CLAUDE.md باز می‌کند؛ دستور شروع را خودش تحویل می‌دهد. لازم نیست بعد هر مرحله done را دستی اجرا کنی. کلاد اجرا، بررسی، کامیت، ثبت پیشرفت و ادامه را انجام می‌دهد. محدودیت نشست یا نیاز واقعیِ دسترسی محیط ممکن است همچنان مانع ادامه خودکار شود؛ این بسته آن محدودیت را دور نمی‌زند.

برای اجرای فقط یک مرحله:

```bat
RUNNER.cmd start-step 1
```

در Linux/macOS:

```bash
bash runner.sh check
bash runner.sh start
```

اگر PowerShell اجازه اجرای فایل نمی‌دهد، سیاست سیستم را دور نزن؛ از ترمینال مجاز استفاده کن: `node tools/runner.mjs setup`، سپس Claude Code را در همان پوشه باز کن و متن START_CLAUDE.md را بده. فرمان‌های node زیر مستقل از wrapper هستند.

## فرمان‌ها

| کار | فرمان |
|---|---|
| وضعیت | `node tools/runner.mjs status` |
| آماده‌کردن مرحله بعد | `node tools/runner.mjs prepare` |
| آماده‌کردن مرحله مشخص | `node tools/runner.mjs prepare 7` |
| بررسی ساختار بسته | `node tools/runner.mjs check` |
| ثبت پایان توسط کلاد | `node tools/runner.mjs complete 7 --commit HEAD` |
| بازکردن مرحله برای اصلاح | `node tools/runner.mjs reopen 7 --cascade` |

`complete` فقط بعد از کامیت واقعی، گزارش COMPLETE و شواهد لازم پیش می‌رود. Runner صحت معنایی تست را تشخیص نمی‌دهد؛ کلاد مسئول اجرای واقعی بررسی‌هاست. تغییر وضعیت یک کامیت جدا دارد تا هش کار به‌طور دقیق در آن ثبت شود.

## نکته‌های اعمال‌شده از درخواست تو

- خود کلاد بعد از انجام و بررسی کار، Git commit محلی می‌سازد و هش را می‌گوید.
- کلاد ابهام‌ها و جزئیات فنی را خودش تصمیم می‌گیرد؛ تصمیم و اثرش را ثبت و به تو اعلام می‌کند. توقف برای تأیید روتین ندارد.
- تصمیم‌های قطعی محصول، مخصوصاً D01–D19، تغییر نمی‌کنند. فلو مرجع رفتار است؛ پروتوتایپ و DS مرجع طراحی‌اند.
- مهلت مراجعه ۲۱ روز و مبلغ مبنای عضویت ۳۰۰٬۰۰۰ تومان، مقدار اولیه دیتابیس‌اند؛ تعرفه و مهلت در کد هاردکد نمی‌شوند.
- تعرفه/شماره حساب/صادرکننده واقعیِ نامعلوم جعل نمی‌شود؛ کلاد قابلیت تنظیم را می‌سازد و نیاز عملیاتی را گزارش می‌دهد.
- Git push و انتشار واقعی سایت در این دستور شروع وجود ندارد.

## فایل‌های اصلی

Requirements.md و reference-inputs/Hamzist_Project_Reference_v1.1.md کپی دقیق سند تو هستند. EXECUTION_CONTRACT.md کاربرد اجرایی جدید را روشن می‌کند. CLAUDE.md قواعد ثابت اجرا، DECISIONS.md تصمیم‌ها، PROJECT_STATUS.md پیشرفت، docs/reports گزارش هر مرحله و ACCEPTANCE_MATRIX.md تمام ۳۳ معیار پذیرش اصل سند را نگه می‌دارند. لینک همه رفرنس‌ها نیز در REFERENCES.md موجود است.

اگر نشست قطع شد `start` را دوباره اجرا کن یا START_CLAUDE.md را به نشست جدید بده. کلاد باید وضعیت واقعی Git و مرحله ناتمام را بخواند؛ اجرای مراحل کامل‌شده از ابتدا لازم نیست.
